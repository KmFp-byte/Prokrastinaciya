# Домашний квест

Небольшой личный сайт для учёта домашних запасов: еда, лекарства, косметика, средства для кожи и бытовая химия. У каждого предмета есть фото и статус: «Достаточно», «Средне», «Кончается» или «Закончился». Предметы со статусом «Кончается» и «Закончился» сами попадают в список покупок, а свои записи туда можно добавлять вручную.

Сайт статический (HTML/CSS/JS без сборки). Вход, база данных и хранение фото работают через [Supabase](https://supabase.com). Каждый пользователь видит только свои данные.

## Структура

```
kvest-site/
├── index.html   — разметка всех экранов (вход, запасы, покупки, форма предмета)
├── styles.css   — светлая пастельная тема (розовый, мятный, белый), адаптив от 360px
├── art.js       — милые SVG-иллюстрации (заглушки категорий, котик) и мягкий фон
├── store.js     — слой данных: демо (localStorage) или Supabase
├── hero-art.js  — пиксельный герой 128×128 (части, цвета, 8 фонов), рисуется на canvas
├── hero.js      — вкладка «Герой»: конструктор, цели, характеристики, уровни, настроение
├── menu.js      — вкладка «Меню»: мои блюда, «Что приготовить сегодня?», ужины на неделю, «Для меню» в покупках
├── diary.js     — вкладка «Ежедневник»: трекер настроения и записи по дням (фон, рамки, стикеры)
├── coloring.js  — раскраски по номерам: галерея и экран раскрашивания
├── coloring-art.js — 12 пиксельных картинок для раскрасок
├── pwa.js       — регистрация сервис-воркера, кнопка «Установить приложение», подсказка для iPhone
├── sw.js        — сервис-воркер (сначала сеть; кэш только для офлайн-заглушки)
├── offline.html — страница «Нет интернета»
├── manifest.webmanifest — описание приложения для установки
├── icon-192.png, icon-512.png, maskable-512.png, apple-touch-icon.png, favicon-32.png — иконки приложения
├── app.js       — логика интерфейса
├── config.js    — ключи Supabase (по умолчанию пустые → демо-режим)
└── README.md
```

## Режимы работы

- **Демо-режим.** Если в `config.js` поля пустые, вход не нужен. Данные и фото хранятся в localStorage этого браузера, сверху видна плашка «Демо-режим». Удобно, чтобы посмотреть дизайн.
- **Supabase.** Если ключи заполнены, включаются вход по почте и паролю, таблицы `items` / `shopping_items` и приватный бакет `item-photos`.

## Вкладка «Герой» (v2)

- При первом входе открывается конструктор «Создай своего героя»: пол, тон кожи, волосы, глаза, рот, аксессуар, верх, низ (у каждой части свой цвет) и фон.
- Причёски, глаза, верх и низ — отдельные наборы для девушки и парня (по 20, первые 5 открыты сразу). В `look` они хранятся строковыми id (`g-bob`, `b-middle`, `b-eyes-calm`, `b-shirt`…); при смене пола подбирается вещь с тем же названием или первая открытая. Рот, аксессуары, цвета и фоны общие.
- Цели трёх видов, каждая привязана к характеристике (Здоровье, Красота, Ум, Быт, Спокойствие):
  - **привычки** — +1 балл, отмечаются раз в день;
  - **навыки** — +2 балла за каждую запись, можно много раз в день;
  - **большие дела** — +3 балла один раз, потом уходят в «Выполнено» (оттуда можно вернуть).
- Уровень = сумма всех баллов. Стоимость уровней по кругу: 10, 15, 20, 25, 30. Каждый уровень открывает по одной новой вещи в каждой части (5 доступны сразу, всего 20), каждые 3 уровня — новый фон.
- Если вчера на сайт не заходили, герой сегодня грустит, пока не будет выполнена первая цель дня.
- Таблицы Supabase: `heroes`, `goals`, `goal_log`. Баллы хранятся в журнале, поэтому при удалении цели они сохраняются.

## Вкладка «Меню» (v3)

- Планируется только ужин: одно блюдо на день, неделя с понедельника, даты — по местному времени.
- «Мои блюда»: название и ингредиенты через запятую. Зелёный чип — продукт есть дома (в запасах со статусом «Достаточно» или «Средне»; совпадение по названию без учёта регистра и «ё», одно название может содержать другое).
- «Что приготовить сегодня?» выбирает блюдо — сначала из тех, для которых всё есть дома и которых ещё нет в плане недели.
- «Заполнить неделю» заполняет только пустые дни начиная с сегодня, без повторов, если блюд хватает.
- Недостающие продукты для ужинов с сегодня до конца недели появляются в «Покупках» в группе «Для меню». «Куплено» ставит найденному предмету запасов статус «Достаточно» или создаёт новый предмет (Еда). «Убрать» скрывает продукт до конца недели.
- Таблицы Supabase: `dishes`, `meal_plan`, `menu_skips`.

## Вкладка «Ежедневник» (v4)

- **Настроение.** Одно настроение на день (можно поменять) и короткая заметка. 9 настроений, у каждого свой цвет и мордочка: Радость, Спокойствие, Любовь, Вдохновение, Усталость, Грусть, Тревога, Раздражённость, Злость. Календарь месяца закрашивает дни цветом настроения, внизу — итоги месяца. Нажми на день — можно отметить настроение за него или открыть запись.
- **Записи.** Текст на каждый день + оформление: фон, рамка (пунктир, сердечки, цветочки, звёздочки, скотч) и 20 стикеров (нажми — добавится, перетащи — подвинется, нажми на наклеенный — уберётся). Сохраняется само.
- **Раскраски по номерам.** 12 картинок, все доступны сразу. Выбери цвет и закрашивай клетки с его номером касанием или проводя пальцем/мышкой; щипок или колёсико — масштаб, два пальца или кнопка ✋ — двигать. Прогресс сохраняется. За каждую впервые законченную картинку герой получает +1 к «Спокойствию» (запись в `goal_log` с `kind = 'coloring'`).
- Таблицы Supabase: `moods`, `diary_entries`, `colorings`.

## Установка как приложение (PWA)

Сайт можно поставить на телефон или компьютер как обычное приложение — с иконкой-домиком и без адресной строки. Работает он только онлайн: при запуске всегда загружается свежая версия.

- **Android (Chrome, Яндекс Браузер, Edge):** откройте сайт → в шапке нажмите «Установить приложение». Если кнопки нет — меню браузера ⋮ → «Установить приложение» / «Добавить на главный экран».
- **iPhone / iPad (Safari):** откройте сайт → «Поделиться» (квадрат со стрелкой вверх) → «На экран Домой» → «Добавить». Подсказка об этом появляется внизу экрана один раз.
- **Компьютер (Chrome, Edge, Яндекс Браузер):** кнопка «Установить приложение» в шапке или значок установки ⊕ в адресной строке.

Технически: `manifest.webmanifest` (пути относительные — сайт живёт в подпапке GitHub Pages), иконки лежат прямо в корне сайта, сервис-воркер `sw.js`. Сервис-воркер всегда берёт файлы из сети и держит маленькую запасную копию оболочки только на случай, если интернет пропал; запросы к Supabase, CDN и Google Fonts он не трогает и не кэширует. Если интернета нет совсем — показывается страница `offline.html` «Нет интернета».

**После обновления файлов на GitHub** увеличьте `CACHE_VERSION` в `sw.js` (например, `kvest-v4-1` → `kvest-v4-2`), чтобы старая запасная копия точно удалилась.

## Как заполнить config.js

1. Откройте проект в панели Supabase → **Project Settings → API**.
2. Скопируйте **Project URL** и **anon / publishable key**.
3. Впишите их в `config.js`:

```js
window.KVEST_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi..."
};
```

Что ещё нужно в Supabase:

- таблицы `items` и `shopping_items` с RLS (`user_id = auth.uid()`);
- **приватный** бакет Storage `item-photos` с политиками, которые разрешают пользователю читать и писать только файлы в папке `<его user id>/`;
- **Authentication → Providers → Email**: отключить публичную регистрацию (Allow new users to sign up = off). Пользователей приглашают через **Authentication → Users → Invite user**;
- **Authentication → URL Configuration**: в Site URL и Redirect URLs указать адрес сайта (например, `https://имя.github.io/kvest-site/`), иначе ссылки из писем-приглашений и писем восстановления пароля не вернут на сайт.

## Запуск локально

```bash
cd kvest-site
python3 -m http.server 8000
```

Откройте <http://localhost:8000>. Если открыть `index.html` двойным кликом (через `file://`), часть функций может не работать, поэтому лучше через сервер.

Для Supabase-режима локально добавьте `http://localhost:8000` в Redirect URLs.

## Почему ключ можно держать открытым

`anon` / publishable key специально сделан публичным: он виден любому, кто откроет сайт, и это нормально. Данные защищают правила **Row Level Security** в базе и политики Storage. Без входа запрос ничего не вернёт, а после входа каждый видит только строки и фото со своим `user_id`. Никогда не кладите в `config.js` ключ **service_role** — он обходит RLS.
